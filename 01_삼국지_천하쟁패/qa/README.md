# 최종 검증(QA) 키트: 삼국지 천하쟁패

> 이 폴더는 **출시 직전 최종 검증자**가 쓰는 도구 상자다. 게임 코드는 고치지 않는다.
> 개발이 끝났다는 신호가 오면 이 문서 순서대로 진행한다.

## 0. 역할과 원칙

> **폰 우선.** 이 게임의 최종 목표는 핸드폰(가로 844×390 기준)이다. 웹·PC에서 아무리 잘 돌아도 폰에서 이상하면 실패다. 모든 판정은 `체크리스트_모바일.md` → 실기기(플레이테스트 S9) 결과를 최우선으로 한다. PC 창 확인은 보조다.

| 원칙 | 내용 |
|---|---|
| 고치지 않는다 | 테스터는 코드·데이터·디자인 파일을 직접 수정하지 않는다. 재현 방법과 수정 제안만 담당에게 넘긴다 |
| 재현이 증거다 | 재현 절차, 시드, 세이브 파일, 스크린샷이 없는 보고는 올리지 않는다. "가끔 그렇다"는 재현율(예: 10회 중 3회)로 쓴다 |
| 고정 빌드로 본다 | 라이브 개발 서버(5174)는 다른 세션이 코드를 고치면 HMR로 게임이 초기화된다. 반드시 **스냅숏 빌드**나 설치본으로 테스트한다 |
| 기준은 문서다 | 판정 근거는 `개발자_전달서.md`(A/B/C), `게임마스터_설계노트.md`(31·37·38·39·40·42장), `게이머_위시리스트.md`(★★★), `design/*.html`(비주얼 바이블·모바일 화면·인물/전장). 기준 밖의 의견은 "제안"으로만 쓴다 |
| 세 갈래로 나눈다 | 모든 이슈는 **개발 / 시나리오 / 디자인** 중 하나의 담당에게 간다(아래 3장). 경계 사례는 주 담당 하나 + 참조 담당을 적는다 |
| 회귀를 잡는다 | 고쳤다는 보고가 오면 그 항목 + 주변 기능을 다시 본다. 고쳐진 것만 보고 닫지 않는다 |

## 1. 진행 순서 (한 사이클)

> 매 사이클 맨 먼저 `망한이유_요건.md` 의 P0 → P1을 판정하고 `results/<시각>/망한이유_판정.md` 에 남긴다. 그 다음 아래 순서를 진행한다.

```
단계 0  빌드 고정        qa/scripts/snapshot-build.sh  → 스냅숏 빌드 + 버전·시각 기록
단계 1  자동 검사        qa/scripts/run-auto.sh         → 타입·단위테스트·데이터검증·QA 프로브 전부, 결과는 qa/results/<시각>/
단계 1b 모바일 자동      npx electron qa/scripts/probe-mobile.cjs <스냅숏> all  (6개 기기 에뮬레이션, 터치만 사용, 저사양 CPU)
단계 2  스모크 테스트    플레이테스트_세션.md 의 S0 (15분) — **폰 크기(844×390, 터치)로 먼저**, PC는 그다음: 실행·새 게임·저장·불러오기·턴·전투가 되는가. 하나라도 막히면 즉시 개발에 S1 보고, 이후 단계 중단
단계 3  체크리스트       체크리스트_개발.md / 체크리스트_시나리오.md / 체크리스트_디자인.md 를 전 항목 판정 (통과·실패·보류·해당 없음)
단계 4  플레이 세션      플레이테스트_세션.md 의 S1~S8 (고난도·장기·예외 상황)
단계 4b 실기기          플레이테스트_세션.md 의 S9 (보급형 안드로이드 + 아이폰, 매 사이클 필수)
단계 5  설치본 검증      Setup.exe 설치 → 실행 → 저장 위치(%APPDATA%) → 제거. 체크리스트_개발.md 의 "설치·배포"
단계 6  보고             보고양식.md 형식으로 담당별 보고서 3개 + 출시 판정 요약 1개
단계 7  재검증           수정 회신이 오면 해당 항목 + 회귀 범위 재실행. 판정이 바뀌면 요약 갱신
```

## 2. 심각도와 출시 판정

| 등급 | 정의 | 예 | 출시 |
|---|---|---|---|
| **S1 치명** | 진행 불가, 데이터 손실, 튕김, 설치 실패, 저작권 위험 | 세이브가 깨져 못 불러옴 / 전투 후 멈춤 / 기존 게임 특기 이름 그대로 사용 | **1건이라도 있으면 출시 불가** |
| **S2 중대** | 핵심 기능이 틀리게 동작하거나 게임이 망가지는 밸런스, A등급 항목 실패 | 첫 달에 적 본거지 함락 / 이벤트 중복 발동 / 군주 포로 후 세력 처리 오류 | **0건이어야 출시** (예외는 사용자 승인 필요) |
| **S3 보통** | 기능은 되나 틀린 표시·불편·고증 오류, B등급 항목 실패 | 조사 "이(가)" / 연호 표기 오류 / 팝업 순서 뒤집힘 | 개수와 내용을 보고, 사용자가 결정 |
| **S4 사소** | 다듬기 수준 | 여백, 정렬, 문구 다듬기 | 출시 후 업데이트 가능 |

**출시 가능(Go)** 조건: **실기기(S9)에서 S1 = 0, S2 = 0**, 모바일 체크리스트 전 항목 판정 완료, S1 = 0, S2 = 0, A1~A7 전부 통과, 스모크 테스트 통과, 설치본 검증 통과, 자동 검사 실패 0.
하나라도 못 채우면 **출시 보류(No-Go)**. 판정 요약에 남은 조건을 적는다.

## 3. 담당 분류 규칙

| 담당 | 맡는 것 | 판단 질문 |
|---|---|---|
| **개발** ("삼국지게임개발계획" 세션) | 엔진·규칙·AI·전투 로직·세이브·성능·튕김·설치·빌드, 수식과 밸런스 수치, UI가 **동작하지 않는** 문제(버튼 무반응, 상태 불일치) | 코드나 수치를 바꿔야 고쳐지나? |
| **시나리오** | 시나리오 배치(세력·군주·수도·장수), 장수 능력치·생몰·관계, 역사 이벤트의 조건·순서·문구, 연호·지명·표기, 대사·설명 문장, 조사 오류 문구, 고증 | 데이터나 문장을 바꿔야 고쳐지나? |
| **디자인** | 화면 배치, 색·글꼴·토큰, 가독성, 겹침·잘림, 정보 위계, 접근성(색약·글자 크기), 터치·폰 기준, 연출·애니메이션, 아이콘·초상 | 보이는 모습이나 화면 구성을 바꿔야 고쳐지나? |

경계 사례 처리:
- **조사 "이(가)"**: 문장은 시나리오, 조사 자동 처리 함수는 개발 → 주 담당 개발, 참조 시나리오.
- **표시값이 틀림**: 계산이 틀리면 개발, 라벨·단위가 틀리면 디자인.
- **밸런스**: 수식·AI는 개발, 시작 배치(병력·도시 수)가 원인이면 시나리오.
- **기능이 아예 없음**: 기준 문서에 있는데 없으면 개발(화면이 필요하면 디자인 참조).

## 7. 프로브 판정 보정 기록

- 2026-11-13 probe-plan BP-06b: 실행도 부족 방침 선택은 엔진이 허용하고 화면이 경고하는 설계 → WARN에서 INFO로 낮춤. 엔진 결과만 보고 "경고 없음"으로 단정하지 말고 UI 코드를 확인할 것.
- 시나리오 시작 연도에 몰년인 장수(예: 208 유표, 219 관우)는 정상 → INFO로만 표시.

- 자동 전투의 "본성 직진" 승률(D5-03)은 0%였지만 UI 경로에서는 열세 공격이 성공한 적이 있음 → 플레이테스트 S5-11로 따로 확인.
- 강 도하·30일 수비 승리·도시 0 즉시 멸망·군주 포로 즉시 계승은 **현재 설계 방침**일 수 있어 FAIL이 아니라 WARN/INFO(방침 질의).

## 5. 자동 검사 스크립트

모두 프로젝트 루트에서 실행한다. 엔진 API가 바뀌어도 멈추지 않도록, 못 쓰는 검사는 `SKIP`으로 표시하고 넘어간다.

| 스크립트 | 보는 것 |
|---|---|
| `bash qa/scripts/run-auto.sh` | 아래 전부 + 타입체크·vitest·데이터검증을 한 번에. 결과 요약 `summary.md` |
| `npx tsx qa/scripts/probe-data.ts` | 시나리오 배치 정합성, 생몰·등장 연도, 군주·수도, 동명이인, 능력치 이미지 범위, 독창성 금지어, 연호표 |
| `npx tsx qa/scripts/probe-sim.ts [시나리오] [년] [시드]` | 헤드리스 AI 장기 진행: 매달 불변식, 이벤트 1회 발동, 수명, 첫 달 점령 수, 통일 속도, AI 턴 시간 |
| `npx tsx qa/scripts/probe-save.ts` | 저장/불러오기 왕복 일치, 결정론, 손상·미래 버전·옛 버전 세이브, 1,000턴 세이브 용량·속도 |
| `npx tsx qa/scripts/probe-battle.ts` | 전투 불변식: 지형 통과 규칙(강·성벽), 30일 제한, 상성표, 일기토·계략 안전핀, 저장/복원 |
| `npx tsx qa/scripts/probe-plan.ts [조합당 횟수]` | 작전 자동 전투(전투개편): 지배·무용 방침, **화면 상성 표기 = 실제 결과**, 위임 가치, 실전 종료·위치·보고서 문장, 약자 역전, 결정론·저장 복원, 실행도, 결과만 보기 속도(폰 환산) |
| `npx tsx qa/scripts/probe-edge.ts` | 39장 예외 상황 강제 재현: 군주 포로, 군주·후계자 동시 사망, 본거지 전멸, 도시 0 세력 등 |
| `npx electron qa/scripts/probe-mobile.cjs <빌드> [기기]` | 폰 에뮬레이션: 터치만으로 진행, 터치 영역·겹침·화면 밖·실제 글자 크기·안전 영역·hover 전용·프레임(저사양)·턴 시간·백그라운드 저장/일시정지·세로 화면·재시작 후 세이브. 화면마다 스크린샷 (디자인 검토용) |
| `npx tsx qa/scripts/probe-text.ts` | 소스·데이터·실행 로그의 조사 오류("이(가)", 받침 뒤 "로" 등), 깨진 문자, 미번역 id 노출 |
- probe-mobile은 화면 흐름을 "앞으로 가는 버튼(→/시작)"으로 따라간다. 목록 문구(예: "영웅들의 시작")를 버튼으로 오인하지 않게 **버튼 요소만** 본다. 화면 구성이 크게 바뀌면 먼저 스크린샷으로 흐름이 맞게 진행됐는지 확인하고 판정한다.
- probe-mobile의 M11(턴 15초 초과)은 알 수 없는 팝업에 막혔을 때도 난다 → 스크린샷 11-after-turns 확인 후 판정.
